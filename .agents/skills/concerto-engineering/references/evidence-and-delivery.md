# 证据、验证、交接与教学

用于能力结论、验证计划、交付报告、开发日志、版本/产物核对，以及讲解 DSH/Cordis/协议概念。

依据：[主设计](../../../../docs/Concerto-Design-v0.3.2.md) §12–§15；[开发日志](../../../../docs/Development-Journal.md)记录当前进度与报告索引。历史测试数字、宿主版本和 Gate 状态放在对应报告，不在 Skill 维护副本。

## 证据与测试分工

- 分开记录用户确认的设计、源码推断、版本特定运行证据和未验证接口。宿主源码存在方法不证明第三方可调用，生成文件或模型自述不证明方法被加载/执行。
- 使用 PASS / FAIL / NOT RUN / UNKNOWN，附实际命令、版本、权限/环境、日志或产物路径与验证范围。缺失数据记 unknown，不用事后估算补齐。
- 当前分工是开发者实现，DSH/Lead 执行功能与真实宿主验收，后续用户明确授权优先。未授权不代跑功能/宿主回归；文档、引用、格式与构建产物身份的静态核对可做，不冒充端到端验证。
- 已授权测试只做与改动相关且有意义的检查；通过后没有新问题不重复扩跑。可逆低影响文档改动无需新增镜像措辞的测试。
- fixture 截图仅证明 fixture；真实截图仅证明可见界面。安装/版本、执行链、审批往返、成果和持久化各自有验证边界，不用一个 PASS 覆盖全部。
- 能力与测试结果绑定具体后端/宿主版本、账号/权限条件和用例；旧版本 PASS 不自动推广到新代码。涉及安装时核对版本、哈希和加载时序，不能只看包大小。

## 交付和日志

- 说明具体问题、最终行为、实际检查和剩余限制；未知能力给出最小验证方法。跨协议/RPC/持久化/状态变更先明确问题、边界、备选、真实失败场景与验证方法。
- 更新确实受影响的主设计、工程 Skill 参考文件、文档指针与日志；不复制第二份设计正文，不覆盖用户历史，不假装已提交 Git。检查未提交改动，保持任务外内容。
- 开发日志记录步骤、依据、决策和坑，测试/验收报告保存版本与原始证据。Gate A1–E 的定义读主设计 §13，当前完成度读最新日志与报告；不要将早期 Gate 清单当成未来每次的固定流水线。
- Gate E 使用现有 run_metric 或明确的对照记录，成功绑定验收；报告样本与未知比例，不承诺团队协作、JSON 或 Skill 路由天然省 token。

## 教学出处（用户要求）

讲 DSH/Cordis/协议概念时，对话回复与 `class/` 教学文件均附可查来源：实际存在的教学章节或宿主内置手册；锁定版本的包 README/类型/源码；实测脚本与日志。内置手册可按主题定位 `cordis-plugin-development`、`editing-cordis-compositions` 或 `cordis-composition-reference`。先核对真实路径，历史目录名不证明文件存在；若缺少教学章节或 API 证据，明确未知及查证方式。

可按需用简短 Learning Checkpoint 解释“DSH 怎么做 → Concerto 复用/隔离什么 → 如何验证”，不要求每次交付教学。面向用户的 C/C++、Lua/Python 背景，用实际调用与代码解释 TypeScript/Node/Cordis，避免堆概念。
