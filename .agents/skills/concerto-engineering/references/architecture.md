用于架构评审、范围取舍、团队配置、角色提示、上下文与产品运行时 Skill 设计。本文的仓库路径相对项目根。

## 先定位权威设计

[主设计](../../../../docs/Concerto-Design-v0.3.2.md)：产品边界读 §0–§3；上下文与提示词读 §4–§5；协作边界读 §6–§7；团队配置/入口读 §10；产品 Skill 读 §4.4/§17.12。只读取受影响部分。

## 做决定时保留的边界

- 侧栏图形化 Team 配置属于产品必需入口，Agent Preset 是优先的原生会话启动方式；两者共享版本化 Team 配置，Preset 不作为配置事实源。配置变化不能无声迁移旧运行/执行。
- Commander 是角色，不是厂商或模型。当前正式来源为 Hosted，可使用已验证的任意 DSH provider；External Commander 的 spike 不等于正式支持，不可静默回退成 Hosted。准入看实际受管决策/工具能力。
- 编码团队保留 Worker 原生 Harness；任务、成果与协作协议归 Concerto，模型与原生工具执行归成员。首版顺序派发，不预建通用 DAG/工作流 DSL、Connector 市场、统一文件系统或第二套 Agent Harness。
- Domain 逻辑不依赖 DSH import；按现有物理布局修改，不为逻辑分层强制拆 npm 包、改语言或建立新服务。

## 上下文与方法

- Project 保存长期目标、约束、确认决定与成果索引；Task 保存本次目标、验收、依赖、问答和检查点；Private Session 保留原生引用。Project Space 不是第四层模型上下文。
- Context Builder 选择用户关键约束、相关项目事实、当前任务契约、必要依赖版本及确认答案，不注入整个团队历史。普通成员不必知道团队结构，必须取得完成当前任务所需的信息。
- 角色职责、流程方法、项目方法分层；简短协作核心常驻，详细角色方法、场景 Skill、工具教程和资料按需读取。persona 不无声替换协作协议。Hosted/外部路径交付语义一致的任务输入，保留原生能力。
- Commander 编写项目 Skill 前应加载插件维护的编写规范；项目方法通过受管工具保存，派发固定版本/内容来源，修订不改变在跑执行。生成、交付、使用反馈和验收证据分开记录。
- 主设计 §4.4.6 的开发经验流程由角色指令、TaskAssignment 与按需读取的流程 Skill 交付。成员先查项目索引，命中后读取，并用任务结果或审查意见交接已证实的成功做法、失败条件和证据。Commander 先核对交接，优先按现有版本规则更新项目 Skill。经验正文仍按需读取，真实会话行为待验收。
- `task-planning` v6 指导 Commander 发布蓝图并提交 `propose_plan`。用户确认当前版本后 Runtime 放行新任务，Host 尝试在原会话续接。结项后用 `offer_project_skill` 在 DSH 原会话询问一次，Runtime 持久化答复。取得明确同意后带来源发布，优先更新匹配条目。真实会话验收待完成。
- 主设计 §4.4.5 的项目成员职责补充由 `manage_member_duties` 和指挥者会话的成员详情维护，按 `projectId + teamId + memberId` 保存和校验版本。Worker 和 Reviewer 的执行冻结正文、作者与哈希，修订或撤销只影响后续派发。它与项目 Skill、单次 `taskContext` 分开，基础角色、用户 persona 与真实权限仍由原有边界管理。真实宿主验收见开发日志。
- 上述产品方法层仍以 §4.4/§17.12 标注的实现范围为准；本工程 Skill 的路由重构不证明运行时 Skill 接口、热发现或工具动态挂载已实现。工具详细教程与可调用 Schema 分开处理，按需加载不保证历史内容被删除或 token 被回收。

## 学习与历史

Native Agent Loop 学习实验留在 `experiments/`，不接入正式 Team Runtime 或阻塞交付；产品化需单独设计决策、真实后端比较与验收。教学按使用者的 C/C++、Lua/Python 背景连接实际代码解释，出处要求见交付指导。

当前阶段、版本和已验证能力查[开发日志](../../../../docs/Development-Journal.md)及对应报告；不要将旧 MVP 清单、spike 或一次验收结果改写为当前全量能力。
