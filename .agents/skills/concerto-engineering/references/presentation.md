# 团队呈现、结构化成果与 Renderer

用于团队主页、任务模块、成员抽屉、主题、结构化对象和 Renderer 改动。

依据：[主设计](../../../../docs/Concerto-Design-v0.3.2.md) §9/§17.9–§17.12；实现定位 `packages/dsh-concerto/src/client/`、该 package 的 `lib/domain/view_objects.mjs` 与相关受管接口。历史截图与 fixture 不等于当前真实宿主效果。

## 页面与职责

- 团队页是默认产品视角：常驻团队目标/状态/待办/成员小精灵，概览、任务、成果分层；任务固定使用看板，点击任务在单处展开详情，不提供列表/看板切换；成员抽屉查看消息、任务与渲染产物，Commander 同样有入口。
- Commander 输出团队计划、任务关系、风险/决策与公共简报，并组织引用；Worker 随执行维护任务方案、步骤、数据、图表和结果证据；Reviewer 维护审查内容。公共简报不替代成员成果。
- Runtime 自动提供状态、审批、阻塞和未知执行；实时图表关联真实 Task/Execution，不因模型画成绿色或用户勾选而完成业务状态转移。
- 主页、任务模块、成员详情引用同一对象，保留作者及编辑权限；公开展示不等于改写权限。实时展示可跟随当前内容，Review/快照/验收证据固定版本。
- 产物数量、公共展示数量与默认展开数量分开。模型自由选内容类型、数量和兼容 Renderer；只有显式 `requiredViews[].requiredForAcceptance: true` 才形成对应验收门禁，自然语言提及或建议视图不自动阻塞。

## 渲染与交互

- 语义内容类型与 renderer 分离；模型提供内容/关系，程序负责布局、主题和格式转换。未知类型/显式引擎/失效引用应可见，不静默画成成功。
- 主设计 §9.7 的严格输出边界已确认、入口收紧待实现：常规模型发布/更新只交付树、节点/边、表格/清单等语义结构，程序负责画图；模型不提交 HTML/CSS、SVG 原文、坐标或 Excalidraw 场景。显式用户导入走独立受限路径，手动布局与历史版本保留。当前源码仍接受原始 HTML/场景，后续需同步工具 Schema、领域校验与发布指南，不可只改提示词或宣称已经封闭这些入口。
- 表格/清单用 HTML/CSS 组件，层级图统一用 `layoutMindmapTree` + 自绘 SVG（`renderer: 'markmap'` 仅作兼容协议标识，预览、全屏和导出共用同一构图），定制图可用原生 SVG；现有手绘白板是 Rough.js + SVG 与 `.excalidraw` v2 子集导出，不得标成完整官方 `@excalidraw` 编辑器。受控 HTML 沿无脚本沙箱边界。
- 结构化发布、局部更新与按需读取沿现有 `publish/patch_view_object`、`list/read_view_object`；团队组织用 `update_team_view`。稳定 ID、CAS、作者/执行归属和证据版本由 Runtime 校验，不从聊天文本猜状态。
- 所有组件和图形消费宿主 `--dsw-*` / `--dsh-*` 主题、字体与交互规范；不硬编码独立色板、不覆写 `.concerto-surface` 颜色、不增设独立深浅色开关。主题解析与对比度策略先查现有实现和主设计，不另建重复系统。
- 用户置顶 `userPinnedRefs`、页签、滚动、展开、画布视角与模型推荐/业务状态分开保存；模型刷新和断线恢复不覆盖用户选择。统一工具栏、中文文本测量和图表预览/展开行为。

## 宿主呈现入口

真实 `tool.call.toolview` 是工具调用的补充卡片；头像、dock、turnTail 不代替团队主页。外部成员没有 DSH 工具调用也应经 Runtime 成果投影可见。host `presentCall/presentResult` 不进入 Client；不伪造宿主工具事件或靠 inject 消息保证可见时间线，不整体替换已被宿主占用的 Chat renderer。

UI 验收关注能否理解团队、定位成员、读取产物；六种图表覆盖是专项检查，不是每个任务的产物数量要求。真实宿主验收、对照截图与 UNKNOWN 项按交付指导记录。
